# 阶段 2：音乐目录 API 设计

## 目标

提供公开只读的歌曲、歌手目录，以及仅管理员可用的新增、修改和删除接口，为前端音乐库和后续 Jamendo 数据导入建立稳定边界。

## 接口边界

- 公开接口：歌曲/歌手列表与详情，无需登录。
- 管理接口：歌曲/歌手新增、局部更新和删除，必须实时校验管理员角色。
- routes 只解析参数、调用 service 和映射业务异常。
- services 处理资源存在性、关联冲突和响应组装。
- repositories 只执行 SQLAlchemy 查询与写入。

## 查询规则

- 列表页码从 1 开始，默认每页 20 条，最大 100 条。
- 歌曲默认按 `popularity DESC, id DESC` 排序。
- `q` 对歌曲名和歌手名进行不区分大小写的模糊搜索。
- `genre`、`language` 使用不区分大小写的精确筛选。
- 歌手列表支持按名称模糊搜索，默认按 `id DESC` 排序。

## 写入和删除规则

- 标题、歌手名不能为空，最长 255 字符。
- 音频和头像地址只接受 HTTP/HTTPS URL。
- 时长与热度必须是非负整数。
- 歌曲引用的歌手不存在时返回 404。
- 删除仍有歌曲的歌手时返回 409，不级联删除歌曲。
- 删除歌曲前显式清理歌单关联、标签关联和播放记录。

## 本阶段不包含

标签管理、歌单、收藏、播放行为写入和向量字段将在后续小步实现。
