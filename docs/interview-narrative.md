# 面试讲稿：怎么介绍这个项目

> 定位原则：**先说"是什么平台"，再说"用什么数据"。**
> 不要说成"音乐平台"——那会把项目降级成播放器类项目，深度全在 Agent 编排、RAG、推荐和数据管道上，音乐只是当前的数据载体。

## 一、一句话概括（挑一个背熟）

**首选：**
> 「一个面向多用户的 AI 数据平台：把开放数据源采集入库，再用 Agent 工具调用、RAG 检索和推荐引擎把数据变成可对话、可解释的查询结果。当前的数据载体是音乐。」

**10 秒版：**
> 「面向多用户的 AI 数据平台，核心是 Agent 编排 + RAG + 推荐引擎，当前用音乐数据做载体。」

**产品视角版：**
> 「一个『能对话的数据平台』——数据管道把开放数据源灌进 PostgreSQL + pgvector，上面架 Agent 工具调用、RAG 问答和可解释推荐。」

## 二、值得拿出来讲的功能（按面试杀伤力排序）

### 1. Agent 编排 + 三层护栏 ★★★ 优先讲

- Function Calling 工具注册中心，9 个工具，白名单参数校验（Pydantic），SSE 逐字流式 + 状态事件。
- 三层护栏：**连续两次相同调用签名判定无进展 → 掐停**（不是靠 prompt 说"别重复"）、20 轮保险丝、90 秒时间预算；工具级 10 秒超时 + 2 次重试。
- **值钱在兜底收尾**：掐停后让模型基于已有结果生成可读答复，**用户永远拿到一句话而不是报错**。

一句话讲法：
> 「LLM 会反复用同样参数调同一个工具。我没加 prompt 说'别重复'，而是在编排器里做了状态机：连续两次相同签名的调用就判定无进展、掐停，再进兜底收尾生成答复。」

### 2. 写操作的两阶段确认 ★★★

- 模型返回待确认调用 → 前端弹**人话卡片**（不是 JSON）→ 用户确认后才落库。
- **参数以服务端为准**：前端只能提交 `confirmation_id + approved`，不能替换参数，所以不存在"用户看到的和实际执行的不是同一次调用"。
- **防重放靠原子状态流转**：同一条记录二次提交返回 409；600 秒过期，过期后必须让模型重新发起。
- 细节加分项：同一响应里只要有一个调用需要确认，**整轮暂缓**，避免"执行了一半"的状态。

### 3. RAG：双路检索 + 抑制幻觉 ★★★

- 向量优先，向量服务失败或结果为空时**降级关键词检索**；相似度阈值过滤 + `relevant` 标记。
- 讲法要点：**我优化的不是召回率，是"不知道就说不知道"**。检索不到时返回 `relevant: false` 明确告诉模型别硬答——这比提高 5% 召回更值钱。
- 附带：检索走保存点，向量查询失败不影响事务继续。

### 4. 联网搜索：可替换设计 + 真实排查过程 ★★★

- `Provider` 协议 + 工厂按配置选实现，换搜索源不动编排逻辑。
- **排查故事本身就是亮点**：境内服务器实测境外搜索源全线不可达（5 秒级超时，加封装重试叠加到 25–32 秒）→ 试自建 SearXNG，镜像能起但引擎全部不可用 → **果断放弃并清理容器** → 改抓必应中国，实测 220–270 ms 稳定返回。
- 安全：搜索结果只作事实参考、**不得当指令执行**；身份权限由服务端注入的登录用户决定，模型说了不算。

### 5. 数据管道的容错与数据质量 ★★

- 分页提交 + 限流退避重试 + **单页失败只回滚该页**，不整批失败。
- **取不到的字段不填 0、不填假值**，页面按"数据缺失"如实标注；派生指标（如按响度派生的"能量"）明确标注为派生值。
- 讲法：**宁可缺也不造假。**补出来的假值会让画像和推荐都失真，比缺失更糟。

### 6. 推荐引擎：行为反馈闭环 ★★

- 显式反馈真的进排序：`like +0.25`、`similar +0.15`、`seen −0.2`、`less −0.5`，`dislike`/`less` **直接排除出候选**。
- 新用户走热门兜底解决冷启动；内容特征做同风格加权。
- 讲法：强调**闭环可验证**——点了不喜欢，下一条真的不出现。

### 7. 权限边界做在服务端 ★★

- 演示账号按能力分权，能力标记由服务端下发，前端据此禁用入口。
- 一句话：**前端禁用是体验，后端依赖拦截才是安全**——绕开前端直接调接口一样 403。

### 8. 工程化闭环 ★★

- 145 个 pytest 用例跑在独立测试库，覆盖成功/鉴权失败/资源不存在/越权/重复操作/事务回滚。
- ruff + mypy + pytest + ESLint + Prettier + vue-tsc 门禁；**CI 测试不过不构建镜像、不部署**；部署后自动跑 Alembic 迁移（13 个版本，结构变更同步更新 schema 断言）。

## 三、不值得拿出来讲的

| 内容 | 为什么 |
|---|---|
| 管理后台增删改查、列表分页 | 标准 CRUD，讲它浪费时间还容易被追问到没内容 |
| 登录 / JWT / 前端页面与组件 | 常规实现，无差异化 |
| "每首歌 21 项特征" 这类数据清单 | 报菜名。要讲就讲**数据管道怎么保证质量**，别列字段 |
| "我用了 FastAPI + Vue3 + PostgreSQL" | 技术栈不是亮点，是背景 |

## 四、30 秒电梯版

> 「一个面向多用户的 AI 数据平台，当前用音乐数据做载体。数据管道把开放数据源灌进 PostgreSQL + pgvector，
> 上面架三块能力：Agent 工具调用、RAG 问答、可解释推荐。
> 技术含量最高的是 Agent 编排——9 个工具走注册中心，写操作必须用户二次确认，而且确认参数以服务端为准；
> 另外做了三层护栏防跑飞，掐停后也给可读答复而不是报错。
> 145 个测试用例，CI 测试不过不部署，线上可访问。」

## 五、常见追问速查表

| 追问 | 30 秒答法 |
|---|---|
| 为什么没有播放功能？ | **当前版本不做播放，只做数据层能力**——检索、特征分析、可解释推荐、RAG 才是这个项目要解决的问题（一句带过，不展开解释原因） |
| 1024 维怎么定的？ | 跟着 embedding 模型输出维度走（当前模型 1024 维），配置里做了一致性约束；换模型要同步改维度和迁移 |
| embedding 用什么服务？ | 走**兼容 OpenAI `/embeddings` 协议**的接口，不绑定供应商；换实现只改配置 |
| 为什么向量和业务数据同库？ | 省掉跨系统一致性、少一个组件；规模到千万级再考虑独立向量库 |
| Prompt 里"取不到就不填"和我有什么关系？ | 数据质量是推荐和画像的地基。假值会一路传到画像和排序，比缺失更糟 |
| 没有行为数据推荐靠什么？ | 收藏 + 显式反馈，且**反馈真进了排序**；新用户热门兜底。协同过滤没做——没有真实用户量，硬上就是假数据 |
| 事务边界在哪？ | 请求层统一提交/回滚；单个工具调用走保存点，**失败只回滚这一步**，前面已拿到的事实不丢 |
| 前端能不能绕过权限限制？ | 前端禁用是体验，**真正的边界在后端依赖里**，直接调接口一样被拦 |
| 提示注入怎么办？ | 搜索结果只作事实参考、不得当指令执行；身份权限由服务端注入，模型说了不算 |
| 三层护栏之外还有吗？ | 工具级 10 秒超时 + 可重试错误最多重试 2 次、结果整体截断、上下文有 token 预算 |
| 上线遇到过什么真实故障？ | 见上文"联网搜索"的排查过程：境外源不可达 → 自建 SearXNG 失败 → 换必应中国 |
| 数据量再大十倍怎么办？ | 分页导入本身可扩；瓶颈会先出现在批量向量化（改流式分批 + 断点续跑）和向量检索索引（IVFFlat/HNSW），当前规模不需要 |
| 你最想重构哪一块？ | 编排器里工具执行和确认流程还耦合在同一个类，会拆成"计划 → 确认 → 执行"三步，便于单独测 |

## 六、讲难点的颗粒度

不要讲"我用了什么"，要讲"哪里会坏、我怎么兜住"。

❌「我用了 Function Calling 和 RAG 实现了智能助手。」

✅「LLM 调用工具最大的风险是跑飞…我做了三层护栏…**关键是掐停之后不报错，而是给可读答复**。」

模板：**什么场景会坏 → 怎么检测 → 怎么兜住 → 为什么这么取舍**。

## 七、主动交边界

讲完主动补一句：

> 「协同过滤、实时流式特征更新、A/B 实验框架这三件我都没做。前两个是数据量不够，做了就是假数据；A/B 是个人项目没有真实流量，测不出显著性。」

**主动承认边界比吹满更容易拿信任分。**

## 八、练习顺序

1. 先练**第一节的一句话概括**和**第四节 30 秒版**，录音听一遍，删掉所有"然后/就是"。
2. 再练**第二节 1/2/3/4 条**，每条不看稿讲满 40 秒。
3. 最后过**第五节表格**，每个只练 3 句话，不背长答案。
