# Agent 循环兜底与工具失败处理

## 背景

`AgentOrchestrator` 的主循环原先只有一道保护：`agent_max_tool_rounds`（默认 5）。
两个问题：

1. **轮数上限被当成"业务判断"**：需要 6 步的正常任务会被直接砍断，而且撞上限时只发一条
   `error` 事件，用户前面等待的结果全部作废。
2. **工具失败只有一档处理**：数据库断连、查询超时这类**瞬时故障**，和参数错误这类
   **确定性失败**，都落进同一个 `except Exception`，既不重试，错误信息也糊成一句
   "工具暂时不可用"，模型无法据此判断该重试还是该改参数。

## 设计目标

- 上限只做**防事故保险丝**，不承担"任务该跑几步"的业务判断。
- 正常的终止条件是"**没有进展**"和"**超出预算**"，不是"轮数到了"。
- 任何终止路径都走**兜底收尾（软着陆）**，尽量把已有结果交给用户，而不是发错误结束。
- 工具失败**先分类再决定**：可重试的有限重试，不可重试的保留原始错误交给模型自纠。

## 一、三层防护

| 层 | 作用 | 配置项 |
|---|---|---|
| ① 无进展检测 | 连续出现**完全相同的工具调用**（工具名 + 参数一致）即判定原地打转 | `agent_no_progress_limit`（默认 2） |
| ② 时间预算 | 单次对话的总时长预算，每轮开始前检查 | `agent_total_timeout_seconds`（默认 90） |
| ③ 轮数保险丝 | 前两层都失效时兜底，值放宽且可配 | `agent_max_tool_rounds`（默认由 5 放宽到 20） |

三者任一触发，都走软着陆，不再产生 `工具调用次数超过限制` 这类硬错误事件。

## 二、软着陆（兜底收尾）

触发收尾时不再执行工具，改为：

1. 向消息追加一条系统指令，要求模型**基于已有信息直接作答**、不要再调用工具；
2. 做**一次**有界的收尾模型调用，把结果流式推给前端；
3. 若这次调用失败、或模型仍未给出正文：
   - 本轮此前已有流式正文 → 直接结束，不重复输出；
   - 本轮始终没有正文 → 推一条固定兜底文案，保证前端一定有收尾。

代价是收尾最多多一次模型调用（有界，只一次）。收益是用户不会拿到"白等一场 + 错误"。

## 三、工具失败处理

异常先分类，再决定动作：

| 类别 | 典型异常 | 处理 |
|---|---|---|
| 可重试（瞬时） | `OperationalError`（含 `statement_timeout` 取消）、`InterfaceError`、`httpx.TimeoutException` / `TransportError`、`TimeoutError`、`ConnectionError`、`EmbeddingProviderError` | 重试 `agent_tool_retry_max` 次，退避 `agent_tool_retry_backoff_seconds * 2**attempt`；仍失败则降级 |
| 不可重试（确定性） | `AgentToolError`、`KeyError`、`ValueError`（含 Pydantic `ValidationError`）、`EmbeddingProviderNotConfiguredError` | 不重试，**保留原始错误文本**交给模型修正参数 |
| 未知 | 其它异常 | 不重试，记 `exception` 日志（带 `session_id`、工具名），对外统一降级 |

**重试的安全前提**：**只有只读工具才重试**，编排层直接按工具的操作类型判断
（`_run_tool(..., allow_retry=tool.operation is ToolOperation.READ)`）。写操作（如
`create_playlist`）失败不重试——重复执行会重复建数据；并且写操作的执行包在自己的保存点里，
失败只回滚这一步，不污染本轮其它步骤。

降级后的错误信息带区分度，不再是同一句话：

- 可重试且重试耗尽 → "工具暂时不可用（请求超时或连接异常），请稍后重试，或缩小查询范围"；
- 未知异常 → "工具暂时不可用，请稍后重试"；
- 确定性失败 → 原始错误文本（模型要靠它改参数）。

## 四、失败的边界（沿用既有设计）

- **工具失败**：降级成一条 `tool` 消息写回对话，让模型自纠；
- **模型调用失败**：属于主轴故障，仍发 `error` 事件结束本轮，不走软着陆。

## 五、测试覆盖（`tests/test_agent_fallback.py`）

1. 瞬时故障重试后成功：只执行一次工具、无 `tool_error` 事件；
2. 瞬时故障重试耗尽：降级为可重试类提示，本轮仍能正常结束；
3. 确定性失败不重试：只调用一次工具，原始错误文本透传给模型；
4. 重复调用触发收尾：提前结束，且不出现"超过限制"错误；
5. 轮数保险丝触发收尾：同上，走软着陆；
6. 时间预算耗尽触发收尾：不执行任何工具。

## 六、未纳入本次范围

- 熔断（同一工具连续失败后快速失败）；
- 失败埋点/指标统计（当前只有日志）；
- 写操作工具的重试排除规则（等真的引入写工具时再做）。
